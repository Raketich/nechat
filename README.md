# nechat

Минималистичный веб-чат с языковой моделью через [OpenRouter](https://openrouter.ai):
стриминг ответа в реальном времени, кнопка «Стоп», обработка ошибок бесплатных моделей,
история сессии. Vue 3 + TypeScript на фронте, Hono (Node) как тонкий прокси, который
держит ключ API подальше от браузера.

## Запуск за 5 минут

1. Нужен **Node.js 20.12+** (`process.loadEnvFile` и `AbortSignal.any`).
2. Получите бесплатный ключ на <https://openrouter.ai/keys>.
3. Скопируйте `.env.example` в `server/.env` и впишите ключ:

   ```bash
   cp .env.example server/.env
   # отредактируйте server/.env: OPENROUTER_API_KEY=sk-or-v1-...
   ```

   Модель можно поменять там же — подойдёт любая с суффиксом `:free` из
   [каталога](https://openrouter.ai/models?q=free).

   > Если чат отвечает «Лимит бесплатной модели исчерпан» — это не ваш аккаунт:
   > популярные `:free`-модели сидят на общем пуле ёмкости провайдера и часто
   > отвечают `429 «rate-limited upstream»`. Лечится сменой `OPENROUTER_MODEL`
   > на другую `:free`-модель и перезапуском сервера (`.env` читается один раз
   > на старте). Постоянный запас: $10 кредитов на аккаунте поднимают суточный
   > лимит бесплатных запросов с ~50 до 1000.
4. Установите зависимости и запустите оба процесса:

   ```bash
   npm install
   npm run dev
   ```

5. Откройте <http://localhost:5173>. Сервер прокси поднимется на `:8787`,
   клиент ходит только на собственный origin `/api/*`.

Проверки: `npm run lint` (типы в обоих пакетах), `npm test` (Vitest).

### Альтернатива: всё приложение в одном контейнере

В прод-режиме сервер сам раздаёт собранный клиент (SPA-fallback включён),
поэтому приложение целиком живёт в одном образе:

```bash
docker build -t nechat .
docker run --rm -p 8787:8787 -e OPENROUTER_API_KEY=sk-or-v1-... nechat
# открыть http://localhost:8787
```

Ключ передаётся переменной окружения при запуске и не запекается в образ.

## CI/CD

- **CI** (`.github/workflows/ci.yml`) — на каждый push в `main` и каждый PR:
  `npm ci` → тайп-чек обоих пакетов → Vitest → сборка клиента.
- **Release** (`.github/workflows/release.yml`) — на каждый мерж в `main`:
  сборка Docker-образа → runtime smoke-тест (контейнеру подсовывается
  заведомо невалидный ключ, проверяются `/`, `/api/health`, SPA-fallback и
  SSE-ответ `/api/chat`) → публикация в `ghcr.io/<repo>:latest` (+ тег по sha).
  Никаких секретов, кроме стандартного `GITHUB_TOKEN`, не требуется.

## Как это устроено

```
client/  Vue 3 + Vite + TS — composables (useChat/useI18n/useTheme), свои компоненты
server/  Hono + TS — POST /api/chat (SSE-прокси к OpenRouter), GET /api/health
```

Поток: браузер → `POST /api/chat` (same-origin через dev-прокси Vite) → OpenRouter
(`stream: true`) → сервер реэмитит SSE-события `delta` / `error` / `done` → браузер
дорисовывает текст по мере генерации.

## Ключевые решения

- **Ключ не попадает в браузер.** Он живёт только в `server/.env` (в `.gitignore`);
  сервер сам добавляет `Authorization` к запросу в OpenRouter. Проверяется вкладкой
  Network: страница отправляет лишь same-origin `/api/*` запросы без ключа.
- **Стриминг и отмена.** Клиент читает `fetch`-поток и парсит SSE. Кнопка «Стоп»
  (или Esc) прерывает fetch; Hono отдаёт `c.req.raw.signal`, и при отключении клиента
  сервер обрывает и upstream-запрос — не платим за генерацию, которую никто не читает.
  Уже полученный кусок ответа остаётся в истории с пометкой «остановлено».
- **Ошибки — не вечный спиннер.** 429 от бесплатной модели, таймаут (жёсткий
  `AbortSignal.timeout(120s)` на сервере) и обрыв сети превращаются в человекочитаемые
  сообщения (ru/en) с кнопкой «Повторить» для ретраибельных случаев. Если обрыв случился
  посреди стрима, частичный текст сохраняется с пометкой «ответ получен не полностью».
- **История переживает перезагрузку** (требование оставило это на наше усмотрение).
  Решение: `localStorage` с версией схемы, без базы данных. Аргументы: задание описывает
  историю «в рамках сессии», сервер не хранит ничего персонального (только проксирует),
  а БД добавила бы стоимость деплоя и эксплуатации без требования, которое её оправдывает.
  «Застывший» стрим при перезагрузке восстанавливается как остановленный, битые записи
  отбрасываются. Черновик ввода тоже выживает.
- **Пушбек заданию про `outline`.** Задание просит убрать стандартную браузерную обводку
  фокуса — но полностью убрать её значит сломать клавиатурную навигацию. Сделан
  компромисс: `outline: none` на `:focus` (мать указатель/тач), но явное видимое кольцо
  на `:focus-visible` (клавиатура). Требование «не выглядит разнобойно» выполнено,
  доступность не потеряна.
- **Свои компоненты вместо UI-библиотеки.** Набор маленький, а библиотека связала бы
  дизайн-токены, темы и фокус-стили своим API; для тестового задания свои компоненты
  и CSS честнее показывают вкус и умение.
- **Свой мини-i18n вместо vue-i18n.** Два словаря на 20 ключей не оправдывают зависимость;
  интерфейс заменяем на vue-i18n за один присест, если вырастет.
- **Модель по умолчанию** — `google/gemma-4-31b-it:free`: на момент работы реальный
  каталог `:free`-моделей OpenRouter проверен запросом к API (прежние дефолты вроде
  `deepseek-chat-v3:free` из каталога исчезли).

## Доступность

Семантические `header`/`main`/`form`, область лога с `aria-live="polite"` и `aria-busy`
во время генерации, Tab по всем интерактивным элементам, Enter — отправить,
Shift+Enter — перенос строки, Esc — остановить генерацию, `prefers-reduced-motion`
выключает анимацию индикатора печати.

## Как использовался ИИ (честный лог)

Писалось в паре с ИИ-агентом (ZCode, модель GLM). Вся ответственность за код — на мне:
каждая строка прочитана и проверена. Где ИИ ошибался и как это вскрывалось:

1. **Валидация тела запроса.** Первый вариант прокси передавал в `parseMessages` всё
   тело `{messages: [...]}` вместо массива `body.messages`. Изолированный юнит-тест
   логики был зелёным (тестировал уже развёрнутый массив), но curl-смоук против
   живого сервера упал с 400. Вывод: тестировать нужно и слой, где тело разбирается.
2. **Реактивность Vue.** Ассистентский объект сообщения создавался как plain object,
   пушлся в `ref`-массив и дальше мутировался напрямую — Vue хранит его как raw,
   сеттеры не срабатывают, UI навсегда оставался на «модель печатает». Поймано
   браузерным тестом: сервер отвечал за 23 мс, а индикатор не исчезал. Лечится
   `reactive()` для мутируемых объектов.
3. **Устаревший дефолт модели.** ИИ по памяти предложил `deepseek/deepseek-chat-v3-0324:free`;
   живой запрос к `https://openrouter.ai/api/v1/models` показал, что этой модели в
   каталоге больше нет. Дефолт заменён на реально существующую `:free`-модель.
4. **Тест проверял не то.** Тест на «удаление HTML» ожидал, что `markdown-it`
   с `html: false` вырежет разметку, а он её экранирует (`&lt;script&gt;`) — что и есть
   безопасное поведение. Ассерт переписан на «нет живых тегов».
5. **DOMPurify вне браузера.** Тесты упали с `addHook is not a function`: без DOM
   санитайзер не инициализируется. Vitest переведён на окружение `jsdom`.
6. **Тема «приклеивалась» к ОС.** Первая версия `useTheme` сохраняла выбор в localStorage
   сразу при первом рендере, после чего «следование за настройкой системы» никогда не
   срабатывало. Найдено при ревью собственных изменений: сохраняем только явный тоггл.
7. **Артефакт тестовой среды.** В браузере автоматизации `locator.press()` не доставляет
   `keydown` в textarea (проверено инструментированием страницы). Enter/Esc перепроверены
   через реальный `KeyboardEvent`; в обычном браузере проблемы нет.
8. **Финальное ревью.** Свой проход по коду вскрыл: Enter во время генерации тихо стирал
   черновик (submit очищал поле, а `useChat` отбрасывал отправку); `<html lang>` оставался
   «ru» для английского интерфейса; восстановление истории принимало битые `error`-объекты
   из localStorage; `engines` обещали Node 20 при фактической потребности в 20.12.
   Всё поправлено, правила восстановления покрыты тестами.
